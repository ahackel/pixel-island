# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm install`, then `npm run dev` — Vite dev server: start page at `/`, tools at `/tools/wardrobe/`, `/tools/parts/`, `/tools/animals/`, `/tools/props/`, `/tools/objects/`, `/tools/flora/`, `/tools/walls/`, `/tools/particles/`, `/tools/scene/`.
- `npm run build` — `tsc --noEmit` (the engine), `tsc --noEmit -p tests` (the tests, with Node's types) and `vite build` into `dist/`; `.github/workflows/pages.yml` publishes it on push to `main`. There is no linter.
- `npm test` — `node --test tests/*.test.ts`: unit tests of the plain rules (ground, terrain and water, walls, ways, front rock). Node only strips types, so tested modules must load in plain Node: no `import.meta.glob` on their import chain and no constructor parameter properties or enums. A game runs these with its own tests.
- `npm run bake` (`scripts/bake.mjs`) — bakes characters and flora into texture atlases with pivots and animations (see `docs/export.md`).
- `npm run check:turntable` — measures hairstyles, hats and garments across the five drawn views.
- Other checks are plain scripts: `node scripts/<name>.mjs` (`parts-check`, `animals-check`, `objects-check`, `check-all`, `history-check`, `brush-check`, `review`). Scripts that need `import.meta.glob` load the code through Vite SSR with the repo root as `root`.

## Layout

Three layers; dependencies point down only (`tools` → `engine` → `shared`):

- `shared/` — game-agnostic utilities: `random.ts`, `files.ts` (local storage and file helpers), `history.ts` (undo), `brush.ts`, `lang.ts`, `pixels.ts`, `shell.ts` (the page shell; its `topBar` builds the pixel `header` of `ui/`), `tools.ts` (the list of tool pages for the header's switcher), `pixel-font.ts` (the 3×5 pixel font from Lop Hop), `pixel-ui.ts` (pixel frames, buttons, labels and speech bubbles as small scaled canvases), `cheats.ts` (the ?cheats button and drawer any game can add), `viewport.ts` (a pixel canvas with eased zoom, pinch, two-finger and trackpad pan, and presses in ground pixels, for games), `base.css`, `ui.css`. `history.ts` and `brush.ts` have no DOM so scripts can test them.
- `ui/` — the pixel interface kit, game-agnostic: `theme.ts` (colours, the icon palette, scale `S`), `icons.json` + `icons.ts` (the shared 9×9 icon library; a game's `src/content/icons.json` adds to and overrides it), `components.ts` (the one place components are defined: button, `choice` with its looks, swatch, slider, range slider, number field, field/fields, section, text field, menu, header, tile grid, toggle, preview frame, confirm, toast, side panel, search and text fields, box, slot, dialog and more), `page.ts` (frame of the pixel pages). Edited in `tools/icons`, all shown in `tools/ui`. New editor UI is built from these, with icons instead of words; reuse before adding, and every new shared component is defined in `components.ts` and added to the overview in `tools/ui/main.ts` (one row per component, variations side by side); `shared/shell.ts` keeps its old helper names (`section`, `row`, `segmented`, `tabs`, `checkbox`, `toggle`, `rangeInput`, `nameTag`, `snapButton`, `topBar`) but builds them from the kit, so every editor shows kit components, and so do the scene editor's dock, floating panels, zoom buttons and dialog (`formDialog`). Still old DOM: the textareas for recipes, the props tool's direction ring, the scene dialog's colour input, the "pick a start" dialog (`pickStart`) and the `walls-proto` bench; `shared/ui.css` keeps only what those and the stage and card layouts need. Every tool page below its header is a `workspace` (panels at the left and right with grips, the middle on the ground; widths kept per tool), its left panel a `library` (a search over tiles of everything the editor edits, filters between them; editors that keep things on the device list them there with the unsaved one as its own tile), and every preview of a thing that turns has the same controls (`turnView`: an arrow at each bottom corner with the tag between them, a drag, the arrow keys) with its extra view options (picture, animate, ground, wind, zoom) as a column of floating buttons at its top right (`viewTools`, the scene editor's look; a choice of several is a `list` choice), and every colour is chosen the same way: up to 16 with `choice(..., 'colors')`, a bar (a cell with an icon instead of a colour, reset or eraser, sits in the same bar), more in a colour field (`colorField`, which `choice` turns into by itself past 16: the chosen colour, a popup of swatches), any colour at all with `colorPicker` (a colour field opening an HSV picker). Panels, popups and the header are `C.panel`, a little darker than a button's paper, so buttons stand out; popups (`popover`) float over the page, so a scrolling panel does not clip them. `shared/game-ui.ts` keeps only the castaway games' HUD and bag slots and re-exports the kit.
- `engine/` — everything that draws or simulates, no page code:
  - `core/`: `puppet.ts` (draws a 32x48 character from joint positions, four facings plus mirrors), `poses.ts` (hand-written poses and `AUTHORED` clips), `palette.ts` (master palette), `stamp.ts` (painted art as text over palette cells, freezing drawn pictures into it, drawing it back with wind sway).
  - `character/`: `base.ts` (body, faces, hairstyles; reads `face-shapes.json`), `items.ts` (two item formats, validation, conversion), `shell.ts` (hair as one shape round the skull), `wear.ts` (condition ageing), `catalog.ts` (wardrobe items from `data/` via `import.meta.glob`, colour swaps), `character.ts` (model and saved roster), `parts.ts` (hand edits to wardrobe items, per catalogue id, laid over by `catalog.ts`), `data/` (the language model's unedited JSON: `sprite-*`, `recipe-*`, `shell-hair`).
  - `flora/`: `flora.ts` (plants grown by rule from part recipes), `flora-catalog.ts` (reads `data/plant-*.json`).
  - `animals/`, `objects/`: renderers and presets behind the animal and object editors.
  - `world/`: `terrain.ts` (height map: one whole level per metre tile, a material per cell (`paint`, `PAINTS`: sand, grass, stone, cave stone, dirt, brick, mine; it gives the top and the step faces, and on a cave's rock its walls), and optionally another for its step faces alone (`side`, `Scene.side`; 0 as the top, `BY_HEIGHT` by the height rule), a water line per map (`water`, level 0 unless set, null for none; `waterOf`), `ROCK_LEVEL` and over solid rock (a cave's, with its floor at `CAVE_FLOOR`); surfaces, cliffs, foam, walkability and plant placement all derive from heights counted from the water line), `ground.ts` (the rules of cell shapes, no drawing: smooth ground sharing its corners with a middle point, cut, ramps, holes, and the walking rules: an edge's ends within a level, no too steep slope), `faces.ts` (painters for the faces of ground and walls by material: stone, brick, mine shoring; the rock wall piece and the terrain's step faces both use them), `island.ts`, `front-rock.ts` (which of a cave's rock is drawn, no drawing: front rock never, rock that hides floor dissolving in a 4×4 pattern down to a stub while it stands in front of the survivor near that floor, a whole joined mass at a time, held until none of it is needed; `cave.ts` draws it), and the runtime: `scene.ts` (saved scene format, validation of anything read back; `Scene.settings`: what lies beyond the map, light, water line and headroom, with the island, cave and sea cave presets), `world.ts` (ground image, camera window, picking, collision; `cutaway` and `cutBelow`, the editor's drawing of the ground cut off above a level and darkened below another, and `waterShown`, its view without water (terrain.ts `bare`)), `actor.ts`, `herd.ts`, `ocean.ts`, `decor.ts`, `flame.ts` (the flame, and `TORCH`: one torch for cave walls and a game's hand, with its particle system), `fish.ts` (fish wandering under the water), `crab.ts` (crabs on the beach and in the shallows), `weather.ts` (cloud, rain, wind, fog and storm amounts and their overlays), `props.ts` (the carried crate), `prop.ts` (props: one `PropKind` over flora, objects, decor and painted kinds; view maps, features, freezing and locks, kinds carried in scene files), `building/` (walls on cell edges and roofs on cells; `walls.ts` the wall catalogue (plank, brick, stone, fence and painted walls) and locks, `pieces/built-wall.ts` brick and stone slabs and the fence, `pieces/painted-wall.ts`, `pieces/door.ts` a door whose leaf swings open, `pieces/ladder.ts` a ladder on a step's face or down a hole; a scene's own walls are `Scene.walls`, in scene coordinates, which `World` turns with the view, blocks walking by (`crosses`, and `cornerBlocked` for a diagonal step past a wall's end) and draws with `wallThings`, which draws the scene's doors and ladders too), `wall-fade.ts` (which of a scene's walls dissolve in front of the survivor, only those the survivor stands behind, a straight run at a time, no drawing), `ways.ts` (ladders, holes and doors, no drawing: `Scene.ladders` up a step of two levels or more, the ladder down a `hole` object, which stands on a hole-shaped cell and keeps its `id`/`to` link (`digHole` upgrades older holes as they are read), and `Scene.doors` on edges, closed, open, locked or hidden, standing in a wall's place and fading with its run; only open doors let a walker through, `canWalk`'s `pass` lets more through for planning), `path.ts` (A* for walking where the player taps; ladders are one more step, a waypoint with a `climb` the actor climbs (`Actor.climb`, the `climb` clip), and closed doors are planned through for the game to open on the way, `World.doorAhead`), `daylight.ts` (time-of-day tints and fade to black over a composed picture), `particles.ts` (particle systems as data, kept in the `pixel-particles` store: the sparks a fire throws and the glow halo round it; an asset attaches one at a point of its picture with `Thing.fx` or a tool item's `fx`, the puppet says where a held tool's point lands, and `emittersOf`/`halos`/`Particles` run them). Spec: `docs/engine-spec.md`.
- `tools/<name>/` — the editor pages (`wardrobe`, `parts`, `animals`, `props`, `objects`, `flora`, `walls`, `particles`, `scene`), each an `index.html` + `main.ts` (often `i18n.ts`, `style.css`). `tools/paint/` is the pixel editor the props, wall and parts editors share; `tools/objects/build-panel.ts` the object panels the props tool reuses; `walls-proto` is a dev-only test bench. `home/` is the start page loaded by the root `index.html`.
- `tests/` — `node:test` unit tests of the engine's plain rules (no DOM).
- `scripts/` — node scripts. `docs/specs/spec-*.md` are the format descriptions given to the model, written by `scripts/make-specs.mjs` from the real renderer; items in `engine/character/data/` belong to the current base body and must be regenerated if it changes.

## Games

A game vendors this repo as a git subtree in its own `engine/` folder (pinned by the game's `.engine-version`) and imports it through a Vite alias `@pixel`. The game's dev server also serves the editors at `/engine/tools/*` (F2 switches), and the editors save into the game's `src/content/` through `shared/project.ts` and `dev/content-plugin.ts`. Anything any game could use belongs here; game rules and content stay in the game. Never import from a game in here.

## Conventions

- Pages are Vite entries listed in `vite.config.ts`; a new tool must be added there, to `shared/shell.ts` (`TOOLS`) and to the start page. Published URLs follow the folder: `/tools/<name>/`.
- Editors save into the project with `saveToProject(name, data)` (`shared/project.ts`): the dev server's `/__save` (`dev/content-plugin.ts`, added to the game's or this repo's `vite.config.ts`) writes `<content dir>/<name>.json`, and `removeFromProject(name)` removes one (the scene editor's renamed scenes); it can't save on a published site. Neither reloads the page. A game's `src/content/face-shapes.json` overrides `engine/character/face-shapes.json`. Editors that keep work on the device (walls, props, objects, animals, parts, flora, the wardrobe's characters) have a "Save to project" menu item (`saveStores(keys)`) that writes those store keys to `<content dir>/store/<key>.json`; `readStore` in `shared/files.ts` (and `loadRoster`) fall back to that file when the device has nothing, so a published game sees them. Add the store key there when a tool gets a new store.
- UI text is English and German via per-tool `i18n.ts` (the props, walls, parts and object pages write both inline with `L(en, de)`); add both when adding strings. `tools/scene` also imports `plantName` from `tools/flora/i18n.ts`.
- Painted things are palette cells in a tone, never free colours (`engine/core/stamp.ts`). Freezing a catalogue prop or wall locks it on the device; games get the lock through scene files (`Scene.carried`) or `wallKind()`.
- User data (saved characters, scenes, props, walls, part edits) lives in browser storage and is exported/imported as JSON; anything read back must be validated (see `engine/world/scene.ts`).
- `docs/plan.md` and `docs/research.md` are history: they describe the removed 3D prototype and the `/lab/` comparison page, which are gone (git history only).
